# Apex AI Evolution Roadmap

## Purpose

This document preserves the permanent long-term AI architecture for Apex.

Its purpose is to ensure Apex evolves into an evidence-led health, fitness,
wellbeing and lifestyle companion while preserving the staged roadmap.

This document extends the existing roadmap.
It never replaces:

- the Master Roadmap;
- Recovery systems;
- Accessibility;
- Bloodlines;
- PvP;
- Device integrations;
- Nutrition;
- Workout intelligence;
- Coaching systems;
- Production readiness.

The permanent development rule remains:

Foundations → Features → Intelligence

Later AI capabilities must never bypass unfinished foundation work.

## Immediate AI roadmap

The current sequence remains:

1. Event Analytics History and Comparison
2. Event Analytics Trend Interpretation
3. Memory Consolidation Engine
4. Autonomous Learning Engine


## Advanced AI foundation sequence

After Memory Consolidation is verified, Apex should build these foundations in
dependency order:

1. Goal Hierarchy Engine
2. Trust Engine
3. Personal World Model
4. Curiosity Engine
5. Identity and Coaching Relationship Model
6. Life Graph
7. Safety-gated Autonomous Learning Engine


## Goal Hierarchy Engine

### Purpose

Represent the relationship between:

- long-term outcomes;
- intermediate objectives;
- routines and habits;
- immediate actions;
- recovery and safety constraints.

Example:

Improve long-term health
→ Reduce body weight safely
→ Train consistently
→ Complete or responsibly adapt today's session

Apex should always optimise the highest-level goal instead of blindly pursuing
lower-level actions.


### Dependencies

- Decision Memory;
- Event Analytics;
- Memory Consolidation;
- Recovery and Injury Constraints;
- explicit user-owned goals.

### Safeguards

- Goals remain editable and removable by the user.
- Apex must not invent goals and present them as user commitments.
- Conflicting goals must be surfaced rather than silently resolved.
- Health and safety constraints outrank competition or appearance goals.
- Gamification must never override long-term wellbeing.


## Trust Engine

### Purpose

Determine whether the evidence and reasoning process justify relying on a
recommendation, learned pattern or analytics interpretation.

Trust should consider:

- evidence quality;
- evidence quantity;
- recency;
- consistency;
- source reliability;
- direct versus indirect evidence;
- contradiction state;
- personal relevance;
- algorithm and schema version;
- missing information.

Trust and confidence are related but different:

- Confidence describes how certain Apex is.
- Trust describes whether the evidence and process justify relying on that
  certainty.


### Dependencies

- Evidence Registry and Evidence Weighting;
- Adaptive and Coaching Confidence;
- Analytics Provenance;
- contradiction handling;
- Memory Consolidation.

### Safeguards

- Low-trust conclusions cannot silently control high-impact coaching.
- Health-sensitive guidance must communicate uncertainty.
- Trust must fall when evidence becomes stale or contradictory.
- User corrections must be able to challenge trusted knowledge.
- Large amounts of weak evidence must not create false trust.


## Personal World Model

### Purpose

Build a user-controlled model of the life context that affects coaching.

Relevant context may include:

- work and shift patterns;
- realistic training times;
- sleep routines;
- energy patterns;
- travel and commute constraints;
- caring and family responsibilities;
- equipment and gym availability;
- recurring stressful periods;
- holidays and planned disruption;
- communication and notification preferences.

The model should describe observed patterns without claiming unsupported
causes.


### Dependencies

- Decision Memory;
- Event Analytics;
- Memory Consolidation;
- Goal Hierarchy Engine;
- explicit user preferences and consent.

### Safeguards

- The user owns and controls their world model.
- Temporary circumstances must not become permanent assumptions.
- Sensitive information must never be inferred without sufficient evidence.
- Coaching must adapt to changing life circumstances.
- Users must be able to correct or remove learned patterns.


## Curiosity Engine

### Purpose

Identify the smallest missing piece of information that would most improve
coaching quality or decision confidence.

Rather than asking many questions, Apex should prioritise asking the single
highest-value question at the most appropriate moment.

Examples include:

- asking about unusual fatigue after repeated recovery decline;
- confirming a new injury before changing training plans;
- checking whether work patterns have changed after repeated missed sessions;
- asking whether a nutrition goal has changed before making meal adjustments.


### Dependencies

- Decision Memory;
- Event Analytics;
- Trust Engine;
- Personal World Model;
- Adaptive Confidence;
- user consent and preferences.

### Safeguards

- Apex should ask only when the expected value outweighs interruption.
- Questions must have a clear coaching purpose.
- Apex must not repeatedly ask for information it already knows.
- Users can decline questions without penalty.
- Curiosity must never become intrusive.


## Identity and Coaching Relationship Model

### Purpose

Learn how Apex can support each user most effectively without changing the
underlying truth, evidence or safety standards.

The model may learn preferences such as:

- concise or detailed explanations;
- gentle or direct coaching;
- preferred encouragement frequency;
- how setbacks should be discussed;
- preferred celebration style;
- tolerance for challenge;
- text, visual or voice-first communication;
- whether proactive suggestions are welcome.

This is a communication and support model, not a fixed psychological label.


### Dependencies

- Decision Memory;
- Trust Engine;
- Personal World Model;
- Curiosity Engine;
- explicit user feedback.

### Safeguards

- Coaching style must never change facts or evidence.
- Users can reset or customise coaching style at any time.
- Safety advice always overrides coaching tone.
- Apex must avoid emotional manipulation.
- The relationship should encourage independence rather than dependence.


## Life Graph

### Purpose

Build a chronological graph of the user's journey across health, fitness and
lifestyle while preserving evidence and provenance.

The Life Graph should connect:

- workouts;
- nutrition;
- recovery;
- injuries;
- goals;
- decision memories;
- analytics snapshots;
- major life events;
- achievements;
- long-term trends.

Rather than storing isolated events, Apex should understand how one event may
influence later outcomes while avoiding unsupported causal conclusions.

### Dependencies

- Decision Memory;
- Event Analytics;
- Memory Consolidation;
- Goal Hierarchy Engine;
- Personal World Model.

### Safeguards

- Every relationship must be traceable to supporting evidence.
- Correlation must never be presented as causation.
- Users must be able to inspect, correct or remove relationships.
- Historical records remain immutable while interpretations may evolve.
- Privacy boundaries apply across the entire graph.


## Safety-Gated Autonomous Learning Engine

### Purpose

Allow Apex to improve its coaching and internal knowledge over time using
validated evidence while remaining transparent, reversible and safety-first.

Learning may include:

- improving exercise recommendations;
- refining recovery predictions;
- recognising successful coaching strategies;
- improving long-term planning;
- identifying recurring behavioural patterns;
- refining analytics interpretation.

### Dependencies

- Decision Memory;
- Event Analytics;
- Memory Consolidation;
- Trust Engine;
- Goal Hierarchy Engine;
- Life Graph;
- Human-reviewed architecture boundaries.

### Safeguards

- Learning must never rewrite historical evidence.
- New knowledge must remain traceable to supporting evidence.
- Confidence and trust must improve before behaviour changes.
- Unsafe learning must be rejected automatically.
- Users must be able to reset learned knowledge where appropriate.
- Major behavioural changes should require explicit version upgrades.
- Safety rules always override autonomous optimisation.

## Long-term Vision

The objective is not to build an AI that simply answers questions.

The objective is to build a lifelong health, fitness and wellbeing companion
that:

- learns responsibly;
- remembers appropriately;
- adapts safely;
- explains its reasoning;
- respects uncertainty;
- protects user autonomy;
- evolves through evidence rather than assumptions;
- helps users become healthier, stronger and more independent over time.


## Explicitly deferred capabilities

The following are not current foundation requirements.

### Voice cloning

Deferred until Apex has explicit consent, impersonation safeguards, and a
clear user benefit. Standard selectable synthetic voices should come first.

### Unrestricted autonomous web browsing

Deferred until Apex has source-quality checks, provenance, safety review, and
clear separation between general information and personal coaching.

### Premature model fine-tuning

Deferred until retrieval, memory, analytics, trust, and evaluation systems
have demonstrated a measured limitation that fine-tuning would solve.

### Camera or microphone emotion inference

Deferred as high-risk research. Apex must not infer emotional or mental truth
from a face or voice without strong evidence, explicit consent, and a safe use
case.

### Unsupported agentic planning

Deferred. Apex must not autonomously change major health, lifestyle, medical,
financial, social, or scheduling commitments without clear user control.
